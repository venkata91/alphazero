Five concepts at the heart of it.

Quick visual primers on the moving parts that show up over and over in an AlphaZero implementation. Keep this open while reading the design doc. Click around, watch the loops; the animations are the explanation.

The five concepts

1 · Monte Carlo Tree Search

A guided search over future positions. We pick a move by running many "simulations" from the current position. Each simulation does three things, in order:

Select — walk down the existing tree, always picking the child with the highest PUCT score. This is the blue path.
Expand — when we hit a node not yet expanded, ask the NN: "what's the prior over each move, and what's your value estimate v for this position?" Create children for every legal move.
Backup — propagate v up the path, flipping sign at every ply (your opponent's good is your bad). Each node tracks N (visits), W (cumulative value), Q = W/N.

After N simulations (50 for TTT, 800 for chess), the move chosen is typically the most-visited child. The visit distribution itself is then used as the training target for the NN's policy head.

Why this matters: A raw NN policy is noisy and shortsighted. MCTS uses many NN evaluations along many possible futures to produce a sharper, better policy than the NN alone. That sharpened policy is what teaches the NN to be better next iteration. This loop is the entire AlphaZero idea.

2 · Replay Buffer

A fixed-size FIFO queue holding training data from recent self-play games. Each ply of each self-play game emits one training tuple:

(s, π, z) s = encoded board state π = MCTS-improved policy at that ply (visit distribution) z = eventual game outcome from that player's perspective (+1 / 0 / -1)

A TTT game produces ~5–9 tuples; a chess game produces ~80–150. The buffer keeps the most recent K tuples (50K for TTT, 1M for chess later). Older ones age out as new self-play arrives. Each training step samples a random minibatch from the buffer.

Why a buffer, not "train on each game immediately"? Consecutive positions inside one game are highly correlated. Random sampling across many recent games breaks that correlation, smooths the gradient signal, and stabilizes training. Standard reinforcement-learning hygiene.

3 · Arena (evaluation gate)

After a training iteration, we have a candidate network. We don't actually know yet whether it's better than the previous best — training is noisy and a step can occasionally make the NN worse.

The arena plays a head-to-head match: new NN vs old NN, say 40 games (split colors so neither side has the white-move advantage). If new wins ≥ 55%, we accept it as the new "best." Otherwise we discard the trained weights and keep the old.

Footnote: The original AlphaZero paper actually dropped this step — they always accepted new networks. Most replications keep it as a safety net during development. We'll include it for Sub-project 1 and can revisit later once the pipeline is stable.

4 · ResNet (Residual Network)

A neural network built by stacking residual blocks. Each block computes:

y = ReLU( x + F(x) ) F(x) = conv → BatchNorm → ReLU → conv → BatchNorm "x" is just the input passed through unchanged (the "skip connection")

The +x on the right is the entire trick. Without it, deep networks are unstable to train: gradients shrink (or explode) as they multiply through many layers, and early layers stop learning. With it, the gradient has a direct path from the loss all the way back to the input — through the skip — so early layers always receive a meaningful gradient signal. Each block then only needs to learn a small correction F(x) to its input, which is an easier learning problem than learning the whole transformation from scratch.

"N blocks of K channels" means: stack N identical residual blocks in series; each block's convolutions produce K feature maps (channels) per spatial position. For TTT: 4 blocks × 32 channels is plenty. For original-AlphaZero chess: 19 blocks × 256 channels. More blocks = deeper = more capacity but slower; more channels = wider = more capacity but more memory.

On top of the residual backbone, AlphaZero attaches two heads:

policy head: 1×1 conv → flatten → linear → action_size logits value head: 1×1 conv → flatten → linear → 1 → tanh (in [-1, +1]) combined loss = CrossEntropy(policy, π) + MSE(value, z) + L2_regularization
Quick intuition for skip connections & vanishing gradients: during backprop, the gradient of the loss with respect to input x is roughly the product of every layer's Jacobian along the way. If each Jacobian has magnitude < 1, the product shrinks to zero through many layers — gradients vanish, early layers stop updating. The "+x" path makes the derivative of y w.r.t. x equal to 1 + ∂F/∂x. That leading "1" guarantees gradient gets through even if the F path's derivative is tiny. We can come back to this with worked numbers later.

5 · PUCT (selection rule inside MCTS)

Not a reward function. PUCT — "Polynomial Upper Confidence applied to Trees" — is the rule that decides, at each step of an MCTS simulation, which child of the current node to descend into. For each candidate move a from node s:

PUCT(s, a) = Q(s, a) + c_puct · P(s, a) · √(Σ_b N(s, b)) / (1 + N(s, a)) └────────┘ └───────────────────────────────────────────┘ exploit: explore: average value scaled by NN prior P seen for a fades as N(s, a) grows

MCTS picks argmax_a PUCT(s, a) at every step of every simulation. Two effects play out across simulations:

Q grows for promising moves as their average observed value rises. U shrinks for already-explored moves because N(s, a) appears in the denominator. So MCTS first explores broadly (guided by the NN prior P), then concentrates visits on whichever moves keep paying off.

c_puct is the only knob — typically 1.0–4.0. Higher = more exploration. The NN's prior P is what makes this polynomial upper confidence (instead of pure UCB1) — the NN biases exploration toward moves it already thinks are promising.

Where the "reward" actually comes from: not from PUCT itself. When a simulation hits a leaf, the value is either (a) the NN's value head output, or (b) the actual game result if the leaf is a terminal position. That value backs up through the tree, updating Q for every node on the path. PUCT then uses those updated Q's to guide the next simulation. So: NN gives priors P and leaf values v → MCTS uses PUCT to walk the tree → backup updates Q → next simulation's PUCT uses the new Q. It's a small feedback loop running within a single move's search.

Putting it together

The AlphaZero self-improvement loop

Each "iteration" of training cycles through these four stages. The loop runs for many iterations (30–50 for TTT; hundreds-to-thousands for chess). Each iteration produces a better NN, which in turn makes the next iteration's self-play games higher quality, which produces a better NN, and so on.

1 · Self-play MCTS(NN) plays itself

Generate N games using current NN to guide MCTS. Each ply produces (s, π, z).

→
2 · Buffer replay_buffer.add(...)

Push new tuples in. Old ones age out (FIFO). Now have a mix of recent positions.

→
3 · Train minibatch SGD on (s, π, z)

NN learns: predict π (policy) and z (value) from s. Many minibatches per iteration.

→
4 · Arena new_NN vs old_NN, 40 games

Accept new NN only if it wins ≥ 55%. Then loop back to step 1 with the new best.

The deep idea: MCTS makes the policy sharper than the raw NN (it sees many moves ahead). Training distills that sharpness back into the NN. The sharper NN makes MCTS even sharper next iteration. Repeat. That is AlphaZero.
